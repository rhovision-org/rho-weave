# Security and operating envelope

Offline prototype only. No third-party dependencies, credentials, shell execution from model input, or networking. JSON parsing and state/action counts have bounds; explicit belief search can still consume significant resources. Use process CPU, memory and time limits and a disposable working directory when handling untrusted input. The CLI writes only user-selected output paths; do not pass sensitive paths. The Python API trusts callers not to mutate model/certificate objects after parsing; the JS runtime trusts a policy table generated by the verified compiler and an independently trusted model hash, not an adversarial table. The digest binds the model, not a signed release or authenticated observations. No external action is executed by either monitor. Unknown observations invalidate the session. Denied operations must never be executed by callers. The declared model must overapproximate external outcomes; missing transitions or inaccurate safety/goal labels can invalidate any guarantee. Do not deploy to production before independent model validation and adapter-level tests.

Version 0.1.1 defensively copies caller-supplied Python monitor inputs and checks the JS table's structure. `PolicySession.fromVerifiedBytes` verifies an externally supplied artifact digest using Web Crypto; this digest must originate from a trusted build/review channel. Direct constructor calls still require a trusted exported table. The public Python `Model` and `Session` internals are not a hostile-code isolation boundary.

## 0.2.0 additions

The source compiler accepts a deliberately restricted grammar and never executes source files. The public input is injected only at quiescence and at most once; internal communication is exhaustively enumerated up to a bounded reduction budget. This does not establish correspondence with an unrestricted Rholang program or the Rholo VM. Do not silently translate unsupported syntax.

The recovery auditor parses one supported literal function shape, not general TypeScript. Do not treat its output as an authenticated source attestation. Pin the exact source revision and verify its digest separately. The included client adapters trust the supplied table, finality anchor and transport; they do not verify on-chain proofs, authenticate network responses, enforce network deadlines or execute transactions. Inconsistent/unknown results are rejected or deferred, never labeled settled. Use an independently reviewed model and trusted transport before operational adoption.

Output artifacts have a 64 MB ceiling and are committed with an atomic same-directory replacement. This does not make concurrent multi-artifact publication transactional. Resource limits are explicit; users should still apply process isolation for untrusted models.
